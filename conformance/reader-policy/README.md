# Supplementary reader-policy corpus

`cases.json` is the immutable-ID D9/D10 reader/runtime handoff from the
[adopted decisions](https://github.com/FAIR-bioHeaders/FAIR-bioHeaders-Specification/issues/211#issuecomment-7017854934).
It is separate from the main carrier manifest's vector count. Each case records
its exact payload SHA-256, operation, expected outcome and governing rule.
Metadata-only checks establish neither file identity nor parent identity.

```sh
python scripts/reader_policy.py
python scripts/reader_policy.py --toolkit /path/to/installed/bin/bioheaders
```

The first command verifies deterministic bytes and independent clause-derived
expectations. The second actually invokes `validate` for metadata cases and
`verify` for carrier cases. Any mismatch exits 1 and is retained in JSON with the
actual diagnostic; no unsupported format or missing runtime is silently skipped.
Passing the reference oracle is not a claim that an installed reader passes.
Use `--write` only when deliberately generating the reviewed new corpus.

Runtime owners must enforce V1–V4 selection before schema validation, R4 for
standard root and typed nested checksums, and selected R1/R12 gzip/YAML policy.
Neither #258 nor #267 closes solely because these shared cases exist. Publication,
consumer adoption/pins and runtime checks remain separate evidence.

The main manifest separately retires historical fixtures whose synthetic parent
checksum ended in noncanonical `B=`. Old payloads stay byte-identical at their
original paths and retain historical expectations in `retired`. New IDs ending
`-canonical-parent` are regenerated by the same builders with a canonical parent;
this isolates both positive acceptance and each negative's intended rejection
rule. The exact old→new crosswalk is machine-readable in the main manifest and
`retirement-crosswalk.json`. The new CR/mixed-ending controls use canonical
parents from the outset. A reader must not score retired valid expectations as
current passes/failures after adopting the revised suite.

The final corpus has 64 cases, including JSON/YAML twins and quoted directive
text controls. `observations/toolkit-0.12.0.json` records the actual published
wheel/version, corpus digest and every result: **35 matched, 29 mismatched,
strict exit 1**. Ten failures concern canonical root/nested metadata encodings,
two concern canonical nested checksums in otherwise correctly checksummed carrier
files, sixteen concern newly refused directive/document-marker forms, and one
concerns wrong FHCRC. This is a failing compatibility receipt, not a runtime
pass. The initial 44-case probe found 24 mismatches; the five additional failures
are the YAML twins of the existing canonical-encoding metadata failures.

The selected gzip positive controls (correct FHCRC, trailing NULs, concatenated
members), quoted-directive values and canonical JSON/YAML records pass the
published toolkit. Unsupported-release cases report their expected distinct
`unsupported-version` result. Execution errors/timeouts cannot count as expected
invalid-record rejections.

CI also re-observes those **exact named published-0.12.0 gaps** with
`--verify-published-receipt observations/toolkit-0.12.0.json` (path relative to
this directory). That calibration checks all 64 outcomes, strict exit, corpus
identity and complete mismatch set. It fails on a changed, fixed, missing or new
result. Its JSON explicitly retains `strictRuntimeExit: 1` and
`runtimeConformance: false`; a matched old-release receipt is not a runtime
conformity pass. New/fixed runtime work uses the strict mode, and earns the
appropriate source issue closure only when the selected behaviours actually pass.
