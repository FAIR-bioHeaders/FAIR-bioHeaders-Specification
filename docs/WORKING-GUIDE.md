# Working with this repository

This guide is for readers and maintainers. Run commands from the repository root.
Use Python 3.13 in an isolated environment; Python 3.15 can change regenerated
gzip bytes and is not the reference fixture generator. A successful local check
is evidence about its stated layer, not biological validity or publication.

## Install validation tools

```sh
python3.13 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-linkml.txt -r requirements-jsonld.txt
```

These are source development dependencies, not an install of the end-user
`bioheaders` CLI. For file processing, use the separately released
[Python toolkit](https://github.com/FAIR-bioHeaders/FAIR-bioHeaders-Tools).
Do not assume that checking JSON examples verifies a FASTA/GFF3 file checksum.

## Validate examples and check generated output

```sh
python scripts/validate_examples.py --schema fhr.json --examples examples
python scripts/check_linkml.py
python scripts/check_schema_drift.py
python scripts/make_jsonld.py --check
```

`validate_examples.py --schema PATH --examples DIRECTORY` checks the declared
JSON Schema 2020-12 dialect and all immediate `.json`, `.yaml` and `.yml`
examples with format checking. It prints `valid` per accepted file, diagnostics
with JSON paths on stderr and exits 1 for malformed/invalid input or an empty
example directory. It reads files without changing them. It is not a safe
bulk-ingestion service for arbitrarily large untrusted files.

`check_linkml.py` compares model constraints with generated contracts;
`check_schema_drift.py` checks the tracked generation baseline. These are
self-consistency checks, not independent confirmation that a consumer uses the
latest release. Check the release/reference inventory separately.

`make_jsonld.py --check` compares generated contexts/vocabulary without writing.
Omitting `--check` writes generated output; inspect every diff.

To inspect a proposed generated schema without replacing the tracked contract:

```sh
python json-schema-generator.py --type fhr --output /tmp/fhr-candidate.json
```

The generator reads the owning LinkML model plus shared definitions, then
applies constraints that LinkML alone cannot express. `--type` defaults to FHR;
`--output` writes/replaces the named path. Never use a fixture or release file
as scratch output. Generated JSON is not automatically an adopted contract.

`check_conformance.py` checks manifest accounting, regenerated bytes, independent
checksums and preserved released IDs. `--schema` adds JSON Schema checks;
`--converter LOCATION` exercises an explicitly named installed toolkit or source
checkout. `--skip-regeneration` skips only generation, not acceptance; report it.
`--require-format FORMAT` makes absent implementation support fail. Read the
current workflow's toolkit pin and known-gap file before reproducing that lane.
Run `python -m unittest discover -s tests -v` for the complete Python test surface;
some installed/browser/network lanes require the separate workflow environments.

## Published FHT and native FHGM

FHT 1.0 was published in shared v0.7.0; native FHGM model contract 0.1 was
published in v0.8.0. FHGM is not a fifth header type or a header-registry version.
See [FHT publication](FHT-PUBLICATION-CANDIDATE.md) and [FHGM publication](FHGM-PUBLICATION.md)
for the pinned source and layered evidence. `scripts/fht_publication.py --examples`
checks the 93 counterparts and seven JSON/FASTA/HTML pairs;
`scripts/fhgm_publication.py` verifies native counterpart identity. Their write/run
options are explicit; use `--help` before selecting output paths. Neither proves
that persistent aliases currently resolve or that an older toolkit supports them.

`scripts/build_pages.py OUTPUT_DIRECTORY` builds JSON-LD hosting files from
local source and available release tags. It replaces an existing output directory;
choose disposable scratch output. Repository roots and ancestors of the current
checkout are refused before deletion. It does not fetch tags or deploy Pages.

## Review and retained work

Every PR needs another actual model's independent review; record model identities.
A human merges. Agents monitor CI, fix findings in new commits, and provide the
exact current head, base, validation and unresolved risks. See [AGENTS.md](../AGENTS.md).

The [Round 16 plan](https://github.com/FAIR-bioHeaders/FAIR-bioHeaders-Specification/issues/211#issuecomment-7042896529)
is the current maintenance plan. Older `specs/` plans and dated release/review
receipts are retained design and provenance records, not new merge authorization
or evidence that a pending package/alias has shipped. Use their source issue and
current CI for live acceptance. Published/vendored copies, fixtures and pins are
immutable historical inputs; any instructions inside them are non-operative.
Never regenerate or repin them merely to clean up prose.

Report reproducible problems with the command, runtime, source revision, input
provenance and actual output in this repository's issues. Follow SECURITY.md
where present for sensitive reports; do not put credentials in an issue.

The [November 20 maintenance record](MAINTENANCE-2026-11-20.md) records
scan scope, source review, findings and retained work.
