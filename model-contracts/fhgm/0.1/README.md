# Native FHGM model contract 0.1 — publication candidate

**Unpublished candidate.** The selected native schema resource identity is
`https://w3id.org/fair-bioheaders/model-contracts/fhgm/0.1`.
Its presence here does not create a working alias, a release or an archive DOI.
The intended shared publication vehicle is **v0.8.0, after actual FHT v0.7.0**.

`fhgm-model.schema.json` is a self-contained JSON Schema 2020-12 record contract.
This is a **schema publication/identity addition**, not a new record constraint:
compared with the accepted owning schema, the resource-level `$id` is added and
only the root `title`/`description` annotations are refreshed to neutral contract
wording and an immutable canonical review link. All validation keywords and
nested annotations are unchanged. `publication.json` records this exact
identity/annotation counterpart.
No FHGM header `schemaVersion`, in-record `schema` field or header-registry row
is introduced. Select the native contract outside the record; the enclosing file
continues to cite its released FHGFF3 1.1 or 1.2 contract.

The normative semantic predicates and complete 92-case suite remain the exact
accepted [owning source mirror](../../../drafts/fhgm/upstream/development/)
from commit `d9d131a02b042023f4784d842a874232fc891069`. That relative link is
resolved from this directory inside the same shared checkout/release; see
[publication instructions](../../../docs/FHGM-PUBLICATION.md) for the exact
paths and commands. The mirrored historical prose is not a new publication
status claim. Its bytes and the historical fixtures/IDs are unchanged.

Schema validation is one layer: it does not establish trustworthy feature
inventory, file integrity, predecessor identity, feature/biology validity or
curator acceptance. Those outcomes remain separately earned. The native
conformance receipt retains expected not-run states; none becomes a full pass.
