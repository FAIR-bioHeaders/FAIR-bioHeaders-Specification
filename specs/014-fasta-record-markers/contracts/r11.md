# Contract: rule R11 and the toolkit behaviour

## Rule text (docs/FORMAT.md)

[R11] In FASTA files (FHR and FHP), FHR header lines should not contain a raw `>` or `@`. Writers
put a value that contains `>` or `@` in a double-quoted YAML scalar and write the characters as
`\x3E` and `\x40`. A file with a raw `>` or `@` stays valid; validators warn. Ordinary `;` comment
lines before the first record should avoid the characters too. GFA and GFF3 are not affected.

## Writer

| Metadata string | FASTA header text |
| --- | --- |
| `contact someone@example.org; contigs > 1000 bp` | `"contact someone\x40example.org; contigs \x3E 1000 bp"` |
| no `>` or `@` | unchanged (byte-identical to fair-bioheaders 0.7.0) |

GFA, GFF3, JSON, YAML, JSON-LD and microdata output hold the real characters.

## Warning

`fhr-fasta-validate`, `bioheaders verify` and `bioheaders validate` on FASTA input print, on
standard error, for each FHR header line with a raw marker:

`FHR: warning: FHR header line N contains a raw '@': kseq-based FASTA readers start a record there; write \x40 in a double-quoted value instead (FAIR-bioHeaders-Specification docs/FORMAT.md R11)`

The exit status is unchanged.
